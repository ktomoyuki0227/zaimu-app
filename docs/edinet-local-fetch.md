# EDINET から有価証券報告書を自動で取得する(ローカル専用)

企業名か証券コードを入れると、有価証券報告書を EDINET から取得し、直近の数年分を自動で取り込みます。
取得はあなたの PC の中だけで行います。公開用のホスティング(静的な配信)では使えません。

## 使うための準備(1 回だけ)

1. EDINET の閲覧サイトで、アカウントを作り、API キーを発行します。
   - メールアドレス・パスワード・SMS の確認コードが必要です。
   - 手順は、金融庁の「EDINET API 仕様書(Version 2)」の「2-3 アカウントの作成と API キーの発行について」にあります。
2. プロジェクトのフォルダで、`.env.example` を `.env` という名前でコピーし、`EDINET_API_KEY=` のあとにキーを書きます。
   - `.env` は git に入りません。キーは他人に見せず、チャットや GitHub にも貼らないでください。
3. 開発サーバーを起こし直します(`npm run dev`)。

API キーが未設定でも、企業を探すところまでは使えます。

## 使い方

1. 最初のページで「企業名・証券コード・EDINET コード」を入れて「企業を探す」を押します。
2. 候補から企業を選び、取得する期間を決めて「有価証券報告書を取得する」を押します。
3. 書類を探して取得し、古い期から順に取り込みます。終わると、その企業の分析ページに移ります。
   - 確認が必要な書類・読み込めない書類(米国基準など)は、反映せずに一覧で知らせます。

## 仕組みと安全のための決まり

- EDINET の API は、ブラウザ(JavaScript)から直接は呼べません(仕様書に明記されています)。
  そのため、開発サーバーに足した小さな中継(`/local-api/edinet`)が EDINET と通信します。
- API キーは中継だけが持ち、画面のコードには渡りません。応答にもログにも含めません。
  読み込む環境変数は `EDINET_` で始まるものだけです。
- 中継は、次のすべてを満たす要求だけを受け付けます。
  - この PC 自身からの接続で、Host が `localhost` 系であること
  - 中継(リバースプロキシ・トンネル)を経由していないこと
  - 同じオリジンの画面からの呼び出しであること(別のポートの `localhost` のページからも呼べません)
  - 自前の画面だけが付けるヘッダが付いていること
  - Origin・Referer が付いていれば、そのホストが Host と同じであること(外のブラウザからの要求を断ります)
- 書類のダウンロードは、同じサーバーの探索で見つかった書類だけです(任意の書類番号を次々に要求して、キーの利用枠を使わせないため)。
- **ngrok などのトンネルで、開発サーバーを外に公開しないでください。** 公開すると、あなたのキーの利用枠が他人に使われます(中継を経由した要求は断りますが、念のためです)。
- 接続先は、EDINET の API とコードリストの公式 URL の 2 つだけです。リダイレクトは追いません。
- 利用規約は「短時間における大量のアクセス」を禁じています。
  - 要求は 1 つずつ、約 1.1 秒以上の間隔を空けて送ります。
  - EDINET から制限(429)やキーの拒否(401・403)を示されたら、10 分間は何も送りません。
  - 1 回の探索で EDINET に問い合わせる日数は、最大 200 日までです(超えたら止まり、続きは次回に回ります)。
  - 探索は、同時に 1 つだけ実行します。
- EDINET からの応答は、大きさの上限(1 書類 30MB)までしか読みません。
- 調べた日の一覧と、取得した書類は `.cache/edinet/` に保存し、同じものは二度取りに行きません。
  ただし、直近 7 日の一覧は、まだ変わりうるので保存しません。`.cache` は git にも、開発サーバーの配信にも含めません。
  保存した書類の合計が 300MB を超えたら、古いものから消します(必要になったら、取り直します)。書き込み途中で途切れた古い一時ファイル(`.tmp`)も、保存のついでに消します。
- 同じ書類を同時に要求されても、EDINET へは 1 回だけ取りに行きます。

## 探し方

書類一覧 API は、日付でしか絞り込めません。そこで、EDINET コードリストにある決算日から、有価証券報告書が提出される時期(決算日から 3 か月以内)を割り出し、提出が集中する期限の前後から順に日付を調べて、見つかったところで止めます。
初回は数分かかることがありますが、2 回目以降(別の企業を含む)は、保存済みの一覧を使うので速くなります。

- 提出期限がまだ来ていない事業年度は、見つからなくても「未提出の可能性」として別に知らせます(取得する年数の枠には数えません)。
- 同じ事業年度に原本(有価証券報告書)と訂正報告書があるときは、**原本を使います。** 訂正報告書は、訂正した部分だけを含む場合があり、財務諸表がそろっている保証がないためです。原本が見つからないときだけ、訂正報告書を使います。

## IFRS の書類について

日本基準に加えて、IFRS(連結)の有価証券報告書も取り込めます。トヨタ自動車・日立製作所の実際の書類で確かめています。
IFRS には経常利益や特別損益の区分が無いので、日本基準と同じ 22 項目には、次のようにそろえています(取り込み後の画面にも、同じ内容を「知らせ」として表示します)。

- 営業利益は、書類の営業利益に合わせます。販売費及び一般管理費は「売上総利益 − 営業利益」で求めるため、その他の営業収益・費用や研究開発費を含みます。書類に営業利益の表示が無い会社は、売上総利益 − 販管費を営業利益とします。
- 営業外収益は金融収益、支払利息は書類の支払利息(無ければ金融費用)を使い、残りは「税引前利益 − 営業利益」との差で合わせます。特別損益は 0 です。
- その他の金融資産(流動)は、有価証券には入れず「その他」に含めます。
- 科目名は会社ごとに違うことがあります(売上債権が独自の拡張科目になる会社など)。売上債権・仕入債務・支払利息・減価償却費の科目が見つからないときは、0 の仮置きとして「確認が必要」にします。

## 使えないもの(今のところ)

- 米国基準・修正国際基準などの書類は、取り込めません(日本基準と IFRS に対応しています)。
- 銀行・保険・証券など、業種別の様式の書類(売上収益が無いもの)は、取り込めません。
- IFRS の科目名は、トヨタ自動車・日立製作所の書類と、標準科目の名前から割り出しています。ほかの会社で科目が見つからなかった場合は、確認画面でお知らせします。
- 決算日が不明な提出者や、有価証券報告書を提出していない企業は、探せません。
- 訂正報告書で数値が直されていても、原本の値のまま取り込みます(上の説明のとおりです)。
- 調べた日の一覧に、あとから新しい提出が加わった場合(遅れた提出など)は、保存済みの一覧に反映されません。取り直したいときは、`.cache/edinet/days` を削除してください。
